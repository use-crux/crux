## Do Not Touch Yet

The following belong to the parked technical questions and should not be implemented, designed, or implied as shipped during the positioning phases:

- New decision-report read models, runtime event schemas, devtools generation-panel changes, or API exports.
- Rationale artifact schemas for routing, consensus, swarm, fallback, retries, or safety boundaries.
- New context API fields, context contract metadata schemas, freshness schemas, freshness-aware matchers, or enforcement lints.
- A new harness-decision matcher library, `crux quality run` output contracts, `crux lint` output contracts, CI review mode, or PR comment formats.
- Definition-centric health pages, suggested-fix surfaces, governance UI, or enterprise governance claims.
- Public decision-provenance specification pages or semantic-convention namespace commitments.
- Adapter APIs, compatibility suites, or public pluggable-runtime-profile contracts.
- Planner APIs or model-assisted context-planning runtime behavior.

If a later docs page needs to mention one of these items, it must be labeled "in progress", "planned", or "experimental" using the status map above, and it must not include API names, schema shapes, matcher names, or read-model details.
