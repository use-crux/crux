Learn · target customer

Find the team with one expensive turn

The best first customer is not “an enterprise using AI.” It is a reachable product team with one repeated model workflow, visible failure costs, enough evidence to test improvements, and authority to try a developer tool quickly.

ICP status: hypothesisValidation target: 10 interviews
Recommended beachhead: AI-native B2B software companies with 5–50 engineers, production model traffic, one measurable workflow, and no dedicated post-training team.

The qualifying workflow

Positive signals
  • At least hundreds of task executions per day—or meaningful human review cost.
  • The input/output/tool contract is reasonably stable.
  • Correctness can be scored or reviewed consistently.
  • Production traces, corrections, labels, or eval cases already exist.
  • A quality, latency, privacy, or unit-economics failure is blocking growth.
  • A technical owner can deploy a library without procurement.
Disqualifiers
  • “We want to use AI” without one bounded job.
  • Low-volume generic chat where a frontier API is already cheap.
  • Constantly changing facts are the main problem.
  • No data rights, no success measure, and no reviewer.
  • The buyer expects Crux to own GPUs, labeling labor, or application delivery.
  • The engagement requires enterprise security certification before any learning.

Jobs to be done

Reliability

“Tell me why this failed.”

Connect what was authored, what entered the turn, what the model did, and which change will prevent recurrence.

Release confidence

“Prove this change is safe.”

Compare prompts, contexts, models, and policies against the same cases and promotion bar.

Economics

“Use less model without losing quality.”

Determine whether routing, better context, or a specialist can meet the protected baseline more cheaply.

Trigger events

  • A provider/model upgrade caused regressions.
  • A team is paying for a frontier model on a repetitive task.
  • Prompt size and latency are growing with every new instruction.
  • A customer requests tenant-specific behavior.
  • Production incidents cannot be reproduced from existing traces.
  • The company has collected user corrections but does not know how to use them.
  • An AI feature works in demos but cannot pass an internal release bar.
Recommended initial use case

Structured decision or transformation with a verifiable outcome

Examples: support-ticket triage, structured extraction, policy classification, deterministic tool selection, code repair, or text transformation with accepted user edits. Avoid leading with open-ended agents or “company intelligence.”

ICP gate

No segment commitment before ten interviews

Choose the beachhead only if at least five interviewees describe substantially the same painful workflow, three can provide evidence, and one agrees to a scoped pilot. Otherwise change the workflow hypothesis, not the whole Crux architecture.

Founder action

Build a 25-company candidate list

Use public product pages, engineering posts, GitHub repositories, launch directories, and founder networks. Record the visible AI workflow, likely trigger, technical contact, and one personalized observation. Do not buy a lead database.
