`@crux/core/quality` is the Quality system's public surface: five values plus
types. Authoring lives in `*.eval.ts` files (or colocated `prompt({ tests })`),
execution in `evaluation.run()` and the [`crux quality` CLI](/docs/reference/local).

```ts
import { evaluate, target, scorers, dataset, cassette } from '@crux/core/quality'
```

## `evaluate()`

Defines an Evaluation. Two call forms — options only (id derived from the file
path at discovery) or explicit id (required for baseline promotion):

```ts
evaluate({ task, data, ... })
evaluate('support.refunds', { task, data, ... })
```

Options:

| Key | What it does |
| --- | --- |
| `task` | Any Crux primitive (`Prompt`, `FlowHandle`, agent, retriever), a plain `(input, params) => output` function, or a `target.*()` wrapper with defaults |
| `data` | Inline case array (`{ name?, input, expected?, trials?, tags?, only?, skip?, expect? }`) or `dataset()` references |
| `expect` | Evaluation-level assertion callback over `CaseContext` — runs for every cell |
| `scorers` | Array of scorer functions (autoevals-compatible) or a factory lambda `(s) => [...]` bound to the evaluation's types |
| `variants` | Named execution overrides (`params`, whole-`task` substitution); `baseline:` names the comparison reference |
| `trials` | Repetitions per case (aggregates carry mean ± SEM, pass@k / pass^k) |
| `gates` | Declarative pass policy: `passRate`, per-scorer `min`/`max`/`minDeltaVsBaseline`, `latency`, `cost`, `consistency` |
| `replay` | Replay mode or `cassette()` declaration |
| `concurrency` / `timeoutMs` / `tags` / `description` | Execution + metadata options |

The returned `Evaluation` is frozen and carries `.manifest` (serializable
structural facts, no execution), `.run(overrides?)` → `Experiment`, and
`evaluate.only` / `evaluate.skip` flags for the runner.

Types flow from the task: case `input` is typed from the prompt's merged
input schema (or the fn's parameter), `ctx.output` from the output schema,
gate keys from scorer names, and variant overrides from the target's
parameter surface.

## `CaseContext` and bound `expect`

The `expect` callback receives one cell's context: `ctx.input`, `ctx.output`,
`ctx.expected`, `ctx.variant`, `ctx.signals`, `ctx.step()` (flow step access
with Standard Schema narrowing), `ctx.score()` (ad-hoc scores), and
`ctx.expect` — a bound, Vitest-honest assertion surface:

- **Value matchers** on any value: `toBe`, `toEqual`, `toContain`,
  `toMatch`, `toBeGreaterThan`, `toSatisfy`, …
- **Always-on namespaces**: `ctx.expect.latency`, `ctx.expect.cost`,
  `ctx.expect.errors`.
- **Capability namespaces** (typed by the task's capabilities):
  `toolCalls`, `steps`, `handoffs`, `retrieval`, `citations`, `safety`,
  `memory`, `routing`, `modelCalls`. Signals come from the observability
  trace; asserting on a signal that was never captured fails loudly with
  guidance (`UncapturedSignalError`), never passes vacuously.
- Assertions hard-throw (Vitest semantics); `ctx.expect.soft` records
  without aborting the cell.

## `target.*`

Wrap a primitive with default parameters, or lift a custom function:

```ts
target.prompt(supportPrompt, { model: 'gpt-5-mini' })
target.flow(researchFlow, { steps: { search: { model: fastModel } } })
target.agent(writerAgent, { tools: { searchDocs: { results: [] } }, maxSteps: 4 })
target.retriever(docsRetriever, { limit: 5 })
target.fn((input: In, params: Params) => out)
```

## `scorers.*`

Code-class scorers run anywhere: `exact`, `contains`, `regex`, `levenshtein`,
`jsonValid`, `jsonDiff`, `retrieval.*` (hit-rate/recall/precision@k, MRR,
NDCG). Model-backed scorers use the `quality.setup()` providers:
`scorers.judge({ name, rubric | choiceScores, select?, model? })`,
`scorers.embeddingSimilarity()`, `scorers.rag.*` (faithfulness,
answerRelevancy, contextPrecision, contextRecall). Any plain
autoevals-compatible function `(args) => Score` also works unmodified.

## `dataset()`

Load portable JSON case files with Standard Schema validation:

```ts
evaluate({ task, data: dataset('./cases/refunds.json', { input: RefundInput }) })
```

## `cassette()` and replay

Replay intercepts model calls at the executor boundary with a normalized
match key (volatile fields excluded). Modes: `live`, `record-new`,
`replay-strict` (CI: miss = cell fails closed with the missing key),
`refresh`. Storage: `.crux/quality/cassettes/<name>.json`, redaction applied
at write time, staleness warning after 90 days. Resolution order:
`--replay` flag → `cassette()` mode → evaluation declaration →
`quality.defaults.replay` → `live`.

## Records

- **Experiment** (`.crux/quality/experiments/<ulid>.json`, gitignored):
  the full matrix — per-cell output/assertions/scores/signals/trace links,
  per-variant aggregates with mean ± SEM, paired `comparison` deltas,
  `gates` results, fingerprints.
- **Baseline** (`.crux/quality/baselines/<id>.json`, committed): an
  explicitly promoted experiment; later runs auto-compare and
  `minDeltaVsBaseline` gates become evaluable. Promote via
  `experiment.promote()` or `crux quality promote`.

## Configuration

The `quality:` block in `crux.config.ts` — see the
[Quality guide](/docs/guides/quality) for a full example: `include`/`exclude`
discovery globs, `dir`, `setup()` (ambient `generate`, `model`, `models`,
`judgeModel`, `embed`), `redact`, and `defaults`
(`trials`/`concurrency`/`timeoutMs`/`replay`).
