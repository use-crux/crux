Crux testing is organized around [`@crux/core/quality`](/docs/reference/crux-core/quality).

```ts
import { expect, quality, suite, target } from '@crux/core/quality'

const q = quality({ id: 'support' })

const support = suite<{ question: string }, { answer: string }>('support', (test) => {
  test('refund policy', {
    input: { question: 'How do refunds work?' },
    expect: (ctx) => {
      expect(ctx.output.answer).toContain('refund')
      expect.retrieval(ctx).toContainHit({ sourceId: 'refunds.md' })
    },
  })
})

await q.evaluate({
  suite: support,
  target: target.prompt({
    prompt: supportPrompt,
    generate: (prompt, input) => generate(prompt, { model, input }),
  }),
})
```

Use the Quality reference for the complete API: suites, prompt targets, retriever targets, flow targets, custom targets, scorers, variant comparisons, feedback export, and cassettes.

## Prompt Resolver Fakes

`@crux/core/testing` ships in-memory fakes for every resolver port, so prompt resolution can be tested through [`createPromptResolver()`](/docs/reference/crux-core/prompts#createpromptresolverports) with no global runtime or observability setup and a clock you control.

| Fake | Port | What it gives you |
| ---- | ---- | ----------------- |
| `recordingObservability()` | `observability` | `scopes` and `artifacts` arrays, plus `contributionPreviews(state?)` for context-contribution assertions. |
| `inMemorySkillSource(skills?)` | `skills` | Registry skills served from a record; unknown ids reject like a failed fetch. `registeredStates` captures activation states. |
| `inMemoryContextCache(clock?)` | `cache` | A fresh, inspectable per-test cache expired by the clock you pass. |
| `fixedClock(start?)` | `clock` | A clock that only moves via `advance(ms)` / `set(ms)`. |
| `collectingDiagnostics()` | `diagnostics` | `warnings` array instead of `console.warn`. |
| `staticPolicy(policy?)` | `policy` | A fixed auto-escape / security-warnings policy. |
| `recordingInstrumentation()` | `instrumentation` | Context-cache hit/miss `events` without runtime hooks. |

```ts
import { createPromptResolver } from '@crux/core'
import { recordingObservability, fixedClock, inMemoryContextCache, collectingDiagnostics } from '@crux/core/testing'

const observability = recordingObservability()
const diagnostics = collectingDiagnostics()
const clock = fixedClock(1_000)
const resolver = createPromptResolver({
  observability,
  diagnostics,
  clock,
  cache: inMemoryContextCache(clock),
})

await resolver.resolvePrompt(config, { input }, schema)
expect(diagnostics.warnings).toHaveLength(0)
expect(observability.contributionPreviews('checked-not-included')).toEqual([])
```
