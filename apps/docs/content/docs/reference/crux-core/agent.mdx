Bound single-turn adapters such as `createOpenAI(...)` return composition
methods including `parallel`, `pipeline`, `consensus`, and `swarm`. Core also
exports their unbound factories for custom executors and tests.

## `agent(config)`

Creates a frozen Agent definition.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `string` | Stable Agent identity |
| `description` | `string?` | Model-facing description when used as a child tool |
| `prompt` | `Prompt` | Prompt, input/output schemas, `use`, and prompt tools |
| `model` | `AnyModel?` | Agent-level model override |
| `tools` | `AnyToolSet?` | Ordinary Tools or child Agent entries |
| `inputBudget` | `InputBudget?` | Default whole-request input pressure settings |
| `prepareStep` | `PrepareStep?` | Callback before each semantic provider call |
| `handoffs` | `(string \| { id, when })[]?` | Swarm routing targets |
| `swarmTools` | `string[]?` | Tool-name allowlist in swarm context |

Returns `Agent<TOwnInput, TOutput, TContexts, TModel>`. `isAgent(value)` narrows
values created by `agent()`.

## Child Agents in `tools`

A direct child Agent is an awaited foreground Tool:

```ts
const parent = agent({
  id: "parent",
  prompt: parentPrompt,
  tools: { research: researchAgent },
});
```

The map key is the provider Tool name; the child's `id` remains its execution
identity. The child description comes from the Agent, then its Prompt. Tool
arguments follow the child Prompt schema: object inputs stay object-shaped,
no-input children receive `{}`, and scalar or mixed-root inputs use `{ input }`.
The exact validated child output becomes the Tool result.

Wrap the child when the model may start it without waiting:

```ts
import { backgroundable } from "@use-crux/core/agent";

const parent = agent({
  id: "parent",
  prompt: parentPrompt,
  tools: { research: backgroundable(researchAgent) },
});
```

See [Backgroundable Agent Work](/docs/reference/crux-core/backgroundable-agent-work)
for the exact input, Work reference, automatic control, status, cancellation,
and process-local lifetime contracts.

Both paths run the child with only its own prompt, `use`, tools, and declared
input. Parent prompt/history/control state is not inherited.

Each direct foreground child invocation opens a distinct nested `agent.run`
below its ordinary `tool.call`, in the same trace as the parent. The child
`agent.run` boundary projects only the authored `agentId` and invoked-Agent
definition reference; it does not project prompt, input, output, tool history,
request, model, control, or handle data. Local Run Detail preserves the
parent/Tool/child hierarchy, and Devtools renders the child as its own Agent
row. Descendant generation and Tool evidence continue to follow the configured
observability capture and redaction policy.

## Composition utilities

### `parallel(options)`

Runs a named map of independent Agents or async functions concurrently.

| Option | Meaning |
| --- | --- |
| `agents` | `Record<string, AgentLike>` |
| `context` | Shared input context |
| `model` | Shared model when an Agent has no override |
| `onError` | `"fail-fast"` or `"continue"` |

Returns `ParallelResult` with `results`, `durationMs`, and optional discriminated
`settled` entries in continue mode.

### `pipeline(options)`

Runs named Agent/function steps in order. Each `input(ctx)` callback receives
the seed context plus prior named outputs. Returns `PipelineResult` with
`status`, accumulated `context`, `finalOutput`, ordered `results`, and
`durationMs`.

### `consensus(options)`

Runs voters and counts `extract(result)` values against a `majority`,
`unanimous`, or numeric quorum. Returns `ConsensusResult` with `result`,
`votes`, `details`, `agreement`, and `durationMs`. Throws `ConsensusError` when
the quorum is not met.

### `swarm(options)`

Runs model-selected handoffs between declared Agents. See the
[Swarm guide](/docs/guides/compositions/swarm) for routing and tool filtering.

### `createCompositions(executor)`

Creates provider-neutral `parallel`, `pipeline`, `consensus`, and `swarm`
functions around an `AgentExecutor`.

## Execution types and test helper

`AgentResult<T>` contains `agentId`, exact `output`, `durationMs`, optional
`usage` and `threadCommit`, and `_meta` operation correlation. An
`AgentExecutor` accepts an Agent plus `ExecuteOptions` and returns ID-free
`AgentResultPayload`; Core finalizes the public result at the `agent.run`
boundary.

`createFakeAgentExecutor(config?)` returns a recorded in-memory executor for
composition tests. Configure per-Agent `{ output }`, `{ transfer, reason }`, or
`{ throws }` behavior, a resolver callback, and optional `fallback: "echo"`.
Its readonly `calls` array records the Agent, options, resolved model, and
execution context for each invocation.

## Coordination building blocks

### `blackboard(config)`

Creates validated shared state. `get`, `getAll`, `set`, `patch`, and `subscribe`
operate on the configured schema/store. `asContext()` exposes read context;
`asTools()` returns focused read/write/patch/clear Tools.

### `handoff(config)`

Creates a typed transfer contract with `inputSchema`, `outputSchema`, and
`transform`. `prepare(input)` returns a validated `HandoffPayload`; optional
storage enables `send()`/`receive()`, and `asContext(payload)` exposes the
prepared transfer to a Prompt.

### `delegate(config)`

Combines an LLM-facing `argsSchema`, a Handoff, and an application-owned
`execute(args, ctx)` callback. `run()` returns the validated `DelegateResult`;
`asTools()` returns the focused `delegate` Tool.
