title: What is Crux?
description: Typed building blocks for everything around your LLM call. Define prompts once, compose the blocks you need, run them with any SDK.
---

Crux is an open-source TypeScript toolkit for the harness around an LLM call — the part of your system that prepares inputs, gives the model tools and memory, validates outputs, measures quality, and explains what happened. It gives you typed prompts, composable contexts, structured memory, retrieval, safety, multi-agent coordination, evaluation, and observability — all SDK-agnostic, all designed to compose.

```ts
import { prompt } from '@crux/core'
import { generate } from '@crux/ai'
import { openai } from '@ai-sdk/openai'
import { z } from 'zod'

const classify = prompt({
  id: 'classify',
  input: z.object({ text: z.string() }),
  output: z.object({
    sentiment: z.enum(['positive', 'negative', 'neutral']),
  }),
  system: 'Classify the sentiment of the given text.',
  prompt: ({ input }) => input.text,
})

const result = await generate(classify, {
  model: openai('gpt-4o'),
  input: { text: 'This is incredible.' },
})

result.object.sentiment // 'positive' — fully typed
```

## What problem does Crux solve?

LLM output quality depends on far more than the prompt string. It depends on the system message, the conversation history, retrieved knowledge, available tools, safety policy, structured output schema, token budget, provider choice, and a dozen other concerns that change request-by-request.

Most apps end up with prompts as scattered template literals, contexts as string concatenation, memory as a custom database table, guardrails as one-off middleware, and evaluation as a manual playground session. Crux gives you typed primitives for each of those concerns and a single composition model that ties them together.

## When should I use Crux?

Reach for Crux when:

- You have **more than one or two prompts** and they share context (brand voice, output format, terminology)
- You need **structured output** with type-safe inference, not parsed JSON
- You want to **swap providers** (OpenAI ↔ Anthropic ↔ Google) without rewriting prompts
- You need **memory** (chat history, semantic facts, agent state) and want it pluggable
- You want **evaluation in CI** — run prompts across a model matrix on every PR
- You're building **multi-agent systems** and need typed handoffs and shared state
- You need **production observability** — devtools in dev, OTel spans in prod

## When should I NOT use Crux?

- **One or two simple prompts.** Raw template strings + `generateText` from the AI SDK is fine. Crux adds value when complexity grows.
- **You want a full orchestration framework.** Crux is a toolkit, not a framework. If you want one system to own chains, agents, RAG, vector stores, and execution end-to-end, use a full framework. Pick Crux when you want lightweight TypeScript primitives around the SDK call you already control.
- **Your runtime can't ship a TypeScript dependency.** Crux is TypeScript-first. There's no Python or Go port.

## What's included

- **Typed prompts & contexts** — Define with Zod schemas, compose declaratively, inspect without executing
- **SDK adapters** — Same prompt runs on Vercel AI SDK, OpenAI, Google GenAI, and Anthropic
- **Memory** — Working (scratchpad), episodic (history), semantic (facts with decay)
- **Compaction** — Sliding window, budget tracking, key facts extraction
- **Evaluation** — Inline test cases, LLM-as-a-judge scoring, CLI runner across a model matrix
- **Multi-agent** — Pipeline, parallel, consensus, swarm composition + typed blackboards and handoffs
- **Plans & Tasks** — Structured planning and task tracking with React hooks for live UI
- **Devtools** — Visual tracing UI for development with CLI dashboard
- **Production telemetry** — OpenTelemetry spans for Datadog, Honeycomb, Grafana
