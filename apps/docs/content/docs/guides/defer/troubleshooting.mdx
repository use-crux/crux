---
title: Defer troubleshooting
description: Diagnose DEFER_* errors without guessing host capabilities.
---

Public defer failures use `CruxDeferError` with a stable `code` and
`docsUrl` (`https://cruxjs.dev/docs/errors/<CODE>`).

```ts
import { CruxDeferError, defer } from '@use-crux/core'

try {
  defer(() => {})
} catch (error) {
  if (error instanceof CruxDeferError) {
    console.error(error.code, error.docsUrl)
  }
}
```

## Quick map

| Code | Typical cause |
| --- | --- |
| [`DEFER_SCOPE_REQUIRED`](/docs/errors/DEFER_SCOPE_REQUIRED) | No active invocation scope (missing host wrapper) |
| [`DEFER_CAPABILITY_MISSING`](/docs/errors/DEFER_CAPABILITY_MISSING) | Scope exists but cannot support this overload (inline unsupported, missing waitUntil/after, named without durable finalization) |
| [`DEFER_SCOPE_SEALED`](/docs/errors/DEFER_SCOPE_SEALED) | Registration after seal |
| [`DEFER_LIMIT_EXCEEDED`](/docs/errors/DEFER_LIMIT_EXCEEDED) | Callback count/nesting/concurrency bounds |
| [`DEFER_REPLAY_UNSAFE`](/docs/errors/DEFER_REPLAY_UNSAFE) | Public `defer()` inside a replayable flow — use `flow.defer()` |
| [`DEFER_TARGET_INPUT_REQUIRED`](/docs/errors/DEFER_TARGET_INPUT_REQUIRED) | Named target called without required JSON input |
| [`DEFER_COMMIT_FAILED`](/docs/errors/DEFER_COMMIT_FAILED) | Strict named staging/finalization failed; response discarded |

Runtime-bound failures still use Runtime codes such as
[`RUNTIME_REQUIRED`](/docs/errors/RUNTIME_REQUIRED).

## Checklist

1. Is the handler wrapped (`withNodeDefer`, `withNextDefer`, `withWaitUntilDefer`,
   Convex `bridge.run`, …)?
2. For inline work: does the host advertise a real lifetime capability?
3. For named work: is `config({ runtime })` present and is
   `durableFinalization: true` on the host lifetime?
4. Inside flows: use `flow.defer()`, never public `defer()`.
5. Catching a named `defer` promise does not undo `DEFER_COMMIT_FAILED` — fix
   the staging failure or use the callback overload for best-effort work.

## Project Index lints

Static analysis reports:

- `defer.replay_unsafe`
- `defer.floating_named_promise`
- `defer.missing_scope`

Named calls without Runtime also reuse `runtime.missing_runtime_config` when
provable. Host capability cannot always be proven statically; runtime still
throws `DEFER_CAPABILITY_MISSING` when the live host cannot honor the call.

## Setup tooling status

Unified project setup aggregation (`crux setup` / contributor planners) is a
separate product track. Until that foundation ships:

- Configure Runtime with `config({ runtime })` and the existing Runtime guides
- Install host wrappers explicitly (`@use-crux/core/defer/node`,
  `@use-crux/next`, serverless ports)
- Use `crux runtime generate` / adapter docs for Runtime artifacts

Do not assume a root `crux setup` command exists yet.
