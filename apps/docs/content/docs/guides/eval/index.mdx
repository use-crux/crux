Crux Quality is the local development loop for AI behavior.

You define a **suite** of cases, run it against a **target**, inspect the resulting **experiment**, compare **variants**, and promote a **baseline** when the candidate is better.

```ts
import { expect, quality, suite, target } from '@crux/core/quality'

const q = quality({ id: 'support', dir: '.crux/quality' })

type SupportOutput = {
  answer: string
  citations: Array<{ sourceId: string; chunkId: string }>
}

const support = suite<{ question: string }, SupportOutput>('support-regressions', (test) => {
  test('refund answer uses docs', {
    input: { question: 'How do refunds work?' },
    expect: (ctx) => {
      expect(ctx.output.answer).toContain('refund')
      expect(ctx.output.answer).toContain('30 days')
      expect(ctx.output.answer).not.toMatch(/maybe|probably/i)
      expect.retrieval(ctx).toContainHit({ sourceId: 'refunds.md' })
      expect.toolCalls(ctx).toHaveCalled('searchDocs')
      expect.toolResults(ctx).toHaveToolResultStatus('searchDocs', 'success')
      expect.grounding(ctx).toHaveCitationForSource('refunds.md')
      expect.budgets(ctx).toHaveTokenUsageBelow(2_000)
    },
  })
})

await q.evaluate({
  id: 'support-v1',
  suite: support,
  target: target.prompt({
    prompt: supportPrompt,
    generate: (prompt, input) => generate(prompt, { model, input }),
  }),
})
```

## The Mental Model

Quality deliberately uses a small set of primitives.

| Primitive   | What it means                                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------------------------- |
| `quality()` | A local workbench scope. It stores experiments, comparisons, baselines, feedback, and cassettes under `.crux/quality`. |
| `suite()`   | A Git-friendly set of test cases. A suite is examples plus expectations, not raw training data.                        |
| Case        | One input plus expected behavior. A bad real query can become one case.                                                |
| `target()`  | The executable thing under test. It can wrap any Crux primitive or app-level path.                                     |
| `expect()`  | Vitest-like assertions over output and execution context.                                                              |
| Experiment  | One immutable run of a suite against one target or several variants.                                                   |
| Variant     | A named candidate target/model/settings combination.                                                                   |
| Comparison  | Baseline vs candidate deltas and gates.                                                                                |
| Baseline    | A promoted reference experiment or variant.                                                                            |
| Cassette    | A deterministic replay fixture for CI and external boundaries.                                                         |

The important design choice is that Crux does not need a separate eval API for every primitive. Prompts, retrievers, and flows have convenience target helpers because they are common. Everything else is still natively evaluable with `target({ run })`, because Quality only needs a typed function from case input to output.

## What Can Be Tested?

All user-facing Crux primitives are testable through Quality.

| Primitive               | Recommended target                                                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------- |
| Prompt                  | `target.prompt({ prompt, generate })`                                                           |
| Context                 | `target({ run: input => context.resolve/inspect through a prompt })`                            |
| Tool or tool middleware | `target({ run: input => call the tool or wrapped tool })`                                       |
| Retriever               | `target.retriever(retriever, options)`                                                          |
| Retrieval pipeline      | `target.retriever(pipeline, options)`                                                           |
| RAG/grounding/citations | `target({ run: input => production RAG path })`                                                 |
| Indexer/chunker/loader  | `target({ run: input => indexer.chunk(...) or indexer.indexDocuments(..., { dryRun: true }) })` |
| Embedding               | `target({ run: input => embedding.embedMany(...) })`                                            |
| Memory                  | `target({ run: input => memory recall/write/read path })`                                       |
| Blackboard              | `target({ run: input => board get/patch/tool path })`                                           |
| Workspace               | `target({ run: input => workspace read/write/list path })`                                      |
| Flow                    | `target.flow(flow, options)`                                                                    |
| Agent/swarm             | `target({ run: input => agent or app-level orchestration })`                                    |
| Guardrail/constraint    | `constraintScorer(c)` as a scorer in `q.evaluate()`, `target({ run })`, or safety evaluators    |
| Scorer/judge            | Use as `scorers` in `q.evaluate()`                                                              |
| Storage adapter         | `target({ run: input => adapter read/write/search behavior })`                                  |

Use the dedicated primitive guide for copy-pasteable examples: [Testing Crux Primitives](/docs/guides/eval/primitives).

## Expectations Inspect The Execution

The `expect` callback receives a normalized execution context. You can assert on output, tool calls, retrieval hits, steps, citations, trace metadata, and identity fields.

```ts
expect: (ctx) => {
  expect(ctx.caseId).toBe('refund-answer-uses-docs')
  expect(ctx.variantId).toBe('candidate')
  expect(ctx.targetId).toBe('support-agent')

  expect(ctx.output.answer).toContain('refund')
  expect(ctx.retrieval.hits.length).toBe(3)
  expect(ctx.toolCalls[0]?.name).toBe('searchDocs')
  expect(ctx.steps[0]?.status).toBe('completed')
  expect(ctx.citations[0]?.sourceId).toBe('refunds.md')
  expect(ctx.traceId).toBeDefined()
}
```

Use domain matchers for common Crux shapes:

```ts
expect.retrieval(ctx).toContainHit({ sourceId: 'refunds.md', chunkId: 'refunds-1' })
expect.retrieval(ctx).toHaveHitCount(3)
expect.toolCalls(ctx).toHaveCalled('searchDocs', { args: { query: 'refunds' } })
expect.toolCalls(ctx).toHaveCalledTimes('searchDocs', 1)
expect.toolResults(ctx).toHaveToolResultStatus('searchDocs', 'success')
expect.steps(ctx).toHaveStatus('draft', 'completed')
expect.citations(ctx).toContainCitation({ sourceId: 'refunds.md' })
expect.citations(ctx).toHaveCitationCount(1)
expect.grounding(ctx).toHaveCitationForSource('refunds.md')
expect.budgets(ctx).toHaveTokenUsageBelow(2_000)
```

## The Development Loop

Start with a tiny suite close to the behavior you care about.

```ts
const support = suite<{ question: string }, { answer: string }>('support', (test) => {
  test('answers refund policy', {
    input: { question: 'How do refunds work?' },
    expect: (ctx) => expect(ctx.output.answer).toContain('refund'),
  })
})
```

Run it against the current implementation.

```ts
const baseline = await q.evaluate({
  id: 'support-baseline',
  suite: support,
  target: currentSupportTarget,
})
```

Run candidates as variants.

```ts
const experiment = await q.evaluate({
  id: 'support-candidates',
  suite: support,
  baseline: 'current',
  variants: {
    current: { target: currentSupportTarget, model: 'gpt-5-mini' },
    candidate: { target: candidateSupportTarget, model: 'gpt-5.1' },
  },
})
```

Compare and gate.

```ts
await q.compare({
  baseline: { experiment, variantId: 'current' },
  candidate: { experiment, variantId: 'candidate' },
  gates: {
    passRate: { minDelta: 0 },
    avgDurationMs: { maxDelta: 500 },
  },
})
```

Promote the candidate when it wins.

```ts
await q.promote({
  id: 'current-support',
  experiment,
  variantId: 'candidate',
  label: 'Current support assistant',
})
```

## JSON Suites

JSON suites are portable fixtures for Git and CI. They can include inputs, expected fields, tags, and metadata, but not runtime assertion callbacks.

```json
{
  "id": "support-regressions",
  "cases": [
    {
      "id": "refund-policy",
      "input": { "question": "How do refunds work?" },
      "expected": { "contains": "refund" },
      "tags": ["billing"]
    }
  ]
}
```

```ts
const support = await suite.json('./evals/support.suite.json')
await q.evaluate({ suite: support, target: supportTarget })
```

Use code suites when you need typed assertions, app-specific logic, or assertions over execution artifacts.

## Auto-discovery

`crux dev` discovers Quality assets by convention. You do not need to list every suite or cassette in config.

Authored suites are discovered under the project root from:

- `*.suite.ts`
- `*.suite.tsx`
- `*.suite.js`
- `*.suite.mjs`
- `*.suite.json`

Committed cassette fixtures are discovered recursively from:

- `*.cassette.json`

Generated and dependency directories such as `node_modules`, `.git`, `.next`, `.turbo`, `dist`, `build`, `coverage`, `generated`, and `.crux/cache` are ignored.

Discovered code suites and committed cassettes appear in devtools before the first experiment run. Local workbench records still live under `.crux/quality`; if a local suite record has the same suite id as a discovered suite, the local record wins so UI edits and annotations are preserved.

## Replay And Feedback

Use cassettes when a suite should run deterministically in CI instead of making live model, retrieval, tool, or HTTP calls.

```ts
await q.evaluate({
  id: 'support-ci',
  suite: support,
  target: supportTarget,
  replay: cassette.replay('./fixtures/support.cassette.json'),
})
```

Use feedback as an inbox, not as an automatic training set.

```ts
await q.feedback.record({
  traceId: 'trace_123',
  rating: -1,
  comment: 'The answer cited the wrong source.',
  expected: {
    sources: [{ sourceId: 'refunds.md' }],
  },
  tags: ['regression'],
})

await q.feedback.writeSuite({
  id: 'support-regressions',
  feedbackIds: ['feedback_123'],
  path: './evals/support-regressions.suite.json',
  tag: 'regression',
})
```
