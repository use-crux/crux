---
title: Multimodal
description: Chat with media, persist it explicitly, generate images, transcribe audio, and retrieve attributed source chunks.
---

Crux uses one media model everywhere: pass usable media to a model, and use an `AssetStore` only when your application wants durable reuse. Model calls never hide storage work.

## Chat with an image or file

```ts
import { prompt } from "@use-crux/core";
import { generate } from "@use-crux/openai";

const inspect = prompt({
  messages: () => [{
    role: "user",
    content: [
      { type: "text", text: "What is in this image?" },
      { type: "image", source: imageBytes, mediaType: "image/png" },
    ],
  }],
});

const answer = await generate(inspect, { model: "gpt-4o" });
```

`source` accepts bytes, a `Blob`, an HTTPS/data URL, or an `Asset`. Invalid media and known unsupported adapter/model combinations fail before provider I/O with safe paths and no payload in the error.

With the AI SDK, keep `useChat` attachments native at the route boundary:

```ts
import { convertToModelMessages } from "ai";
import { createUIMessageStreamResponse, stream } from "@use-crux/ai";

export async function POST(request: Request) {
  const { messages } = await request.json();
  const result = await stream(chatPrompt, {
    model,
    messages: await convertToModelMessages(messages),
  });
  return createUIMessageStreamResponse(result);
}
```

Convex Agent stays Convex-native: pass AI SDK image/file parts to `Agent` or a continued thread. Convex Agent owns its file lifecycle, thread history, and autosave threshold; Crux does not duplicate those writes.

## Persist only when you need reuse

```ts
import { prompt } from "@use-crux/core";
import { inMemoryAssetStore } from "@use-crux/core/storage";
import { generate } from "@use-crux/openai";

const assets = inMemoryAssetStore();
const stored = await assets.put({
  type: "data",
  data: imageBytes,
  mediaType: "image/png",
});

const image = await assets.get(stored.ref);
const reuse = prompt({
  messages: () => [{ role: "user", content: [{ type: "image", source: image }] }],
});
await generate(reuse, { model: "gpt-4o" });
```

Persistence is an ordinary application step. If `put()` fails after image generation, handle or retry that storage operation; do not regenerate the image.

## Generate an image

```ts
import { generateImage } from "@use-crux/openai";

const result = await generateImage({
  model: "gpt-image-1",
  prompt: "A restrained editorial illustration of a quiet canal",
});

const stored = await assets.put(result.image); // optional
```

Generated images are immediately usable data assets. Anthropic intentionally does not export `generateImage`.

## Transcribe audio

```ts
import { transcribe } from "@use-crux/openai";

const transcript = await transcribe({
  model: "gpt-4o-mini-transcribe",
  audio: { type: "data", data: wavBytes, mediaType: "audio/wav" },
});

console.log(transcript.text, transcript.segments);
```

Transcription exposes validated seconds-based segments when the provider supplies measured timing. Anthropic intentionally omits this operation; Google's composed transcript route returns text with empty timing arrays and rejects timestamp requests rather than inventing timing.

## Ingest and retrieve media

```ts
import { fileSource } from "@use-crux/ingest";

const source = fileSource(storedAudio, {
  namespace: "meetings",
  sourceId: "weekly-sync",
  media: { transcribe: ({ audio }) => transcribe({ model: "gpt-4o-mini-transcribe", audio }) },
});

await meetingIndex.indexDocuments(source.documents());
const [hit] = await meetingRetriever.retrieve("launch date");

console.log(hit.source.id, hit.source.location);
```

Image and visual-PDF ingestion bind an application-owned semantic description function through `media.describe`; audio binds `media.transcribe`. Retrieval returns structured, validated attribution: `source.id` plus allowed URL/path/AssetRef/media type and page/time narrowing, while vector metadata remains locator-free. Retrieval never hydrates media. Only if the application needs the original should it explicitly call `assetStore.get(hit.source.assetRef)`.

## Privacy and errors

Crux observability records bounded media facts, never bytes, base64/data URLs, bearer refs, provider file IDs, filenames, or signed URL details. `InvalidMediaSourceError`, `UnsupportedCapabilityError`, storage errors, and empty image/transcript errors are safe to surface without logging the original payload.
